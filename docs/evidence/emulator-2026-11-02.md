# Emulator run, 2 Nov 2026

Environment: IWSDK 1.1.0-rc.2 dev server, managed headless Chromium (software
rendering), IWER emulating a Meta Quest 3 in AR with hand input. Driven by
`test/drive.sh` then `test/drive2.sh` (IWSDK CLI `xr` commands); state read
with `test/read-state.mjs`. Frame rates below come from software rendering and
are **not** headset performance.

Right hand, wrist at (0.05, 1.15, -0.30), pose "flat", palm up:

```
flat     tracked=True place=palm   b=0.000 s=0.000 mood=calm  blooms=0 target=middle
tilt 35° tracked=True place=middle b=0.049 s=0.095 mood=joy   blooms=1 target=index
```

Tracking loss, tip-back and palm-down, after the hand-switch fix:

```
hand-right disconnected   tracked=False place=middle s=0.095 mood=waiting blooms=1
reconnected               tracked=True  place=middle s=0.094 mood=calm    blooms=1
fingers tipped up 30°     tracked=True  place=palm   b=-0.033 mood=calm   (slid back, held at wrist edge)
palm turned down          tracked=True  place=palm   mood=cling            (no movement)
palm up again             tracked=True  place=palm   mood=calm
metrics: lossEvents=1 longestLossMs≈22 264 handSwitches=0 handedness=right
```

Bug found and fixed in this run: the first version moved Mote to the other
(idle, hip-height) hand the instant the right hand disconnected, leaving it
stuck clinging. Now Mote waits on its own hand; it switches only after 3 s,
and only to a palm-up hand.
